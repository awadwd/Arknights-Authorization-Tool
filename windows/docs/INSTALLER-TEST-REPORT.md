# 安装器无人值守自测报告

> 日期：2026-10-25 · 被测包：`1.0.0-beta.4`（138.9 MB）· 环境：Windows，普通用户（无管理员）

## 一、结论

**17 / 17 场景通过，全程 38.8 秒，无任何人工点击。**

安装器在「新建 / 覆盖 / 残留 / 只读 / 中文空格路径 / 深层路径 / 目标被文件占用 / 程序正在运行 /
目录不可写 / 安装包损坏 / 卸载 / 重复卸载 / 清数据 / 误删保护」这些情况下行为都符合预期，
出错时都给明确退出码和可读原因，不会静默半装。

结论：**可以打第一个正式包**，但版本号策略需要先定（见末节）。

## 二、为自动化补上的能力

改之前安装器根本没有静默安装：`/quiet` 只对卸载生效，安装永远弹窗口等用户点「安装」，
自动化无从谈起。现在 `Install()` 是 GUI 和静默共用的唯一实现，两条路径行为一致。

| 参数 | 作用 |
|---|---|
| `/silent`（`/s`、`/quiet` 同义） | 无窗口、无弹框，只靠退出码和日志表达结果 |
| `/dir=路径` | 指定安装目录（不带则用默认 `%LOCALAPPDATA%\Programs\…`） |
| `/desktop` `/startmenu` | 建快捷方式（静默模式默认**不**建，避免批量部署污染桌面） |
| `/startup` | 写开机自启 |
| `/launch` | 装完立即运行 |
| `/uninstall` `/quiet` | 卸载 |
| `/keepdata` / `/purge` | 保留 / 删除用户数据（默认保留） |
| `/datadir=路径` | 覆盖用户数据目录（部署可重定向，测试可隔离） |

退出码（勿随意改动，脚本依赖）：

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 用户取消 |
| 2 | 未安装 |
| 3 | 安装包不完整（无 payload） |
| 4 | 磁盘空间不足 |
| 5 | 目标不可写 / 被占用 |
| 6 | 其它失败 |

日志：`%LOCALAPPDATA%\AkPassport-setup.log`，**放在数据目录之外**，卸载（含 `/purge`）后仍保留。

## 三、这一轮修掉的真实缺陷

| # | 问题 | 后果 | 处理 |
|---|---|---|---|
| 1 | `DisplayVersion` 取自 `AssemblyName.Version` | 装的是 `beta.4`，「设置 → 应用」显示 `1.0.0`，用户报版本时无法定位 | 改读 `InformationalVersion` 并截掉 `+` 元数据 |
| 2 | `KillRunningApp` 只调 `CloseMainWindow()` | 本程序默认「关闭即最小化到托盘」，窗口只是隐藏、文件锁没松 → **覆盖安装直接失败** | 礼貌关闭后 1.2s 未退出就 `Kill(entireProcessTree)` 并确认 |
| 3 | 卸载未安装的目标返回 0 | 自动化脚本会把「什么都没做」当成功 | 返回 2；显式 `/dir` 不存在也按未安装处理 |
| 4 | 解压前只比 `StartsWith(目录)` | `C:\Apps\App` 会误放行 `C:\Apps\AppEvil\…`（目录穿越） | 补尾部分隔符再比较 |
| 5 | 无磁盘空间预检 + 清理失败全吞异常 | 解压到一半才失败，用户拿到半装目录且只看到「写入文件失败」 | 解压前按 payload 实际大小预检；清理失败逐条记日志 |
| 6 | 安装路径输入框是只读的 | 只能一层层点「浏览」，不能粘贴路径 | 可输入/粘贴/拖入文件夹；自动去掉引号、展开 `%ENV%`、去尾部分隔符；逐段校验非法字符与保留名 |

## 五、测试怎么做到「不碰真实安装」

本机是**已安装**状态（注册表项存在、真实用户数据 219 MB），直接测就会互相污染。脚本的做法：

1. **进入前**：把 `Uninstall\AkPassportWin` 全部键值、`Run` 自启值、桌面/开始菜单两个 `.lnk`
   备份到 `_test/_guard`，再从系统里摘掉 —— 模拟一台干净机器。
2. **过程中**：所有安装落在 `_test/sandbox`；卸载一律显式传 `/dir=`，
   绝不依赖注册表推断（否则可能把真实安装目录当目标）；`/purge` 只对沙箱里自建的数据目录执行。
3. **退出时**（`finally`）：原样还原，并**逐值比对**注册表，不一致会打印失败提示。

> 期间有 3 个中间产物目录被清掉，真实安装目录、用户数据、桌面快捷方式均未受影响。

## 六、还没覆盖到的

| 项 | 说明 |
|---|---|
| 真实磁盘写满 | 需要小容量 VHD，成本高于收益；已改为验证预检逻辑与错误码 |
| 杀软 / EDR 实时锁文件 | 只能靠真机长期观察，脚本无法稳定复现 |
| Windows 10 无 WebView2 | 会弹提示，但「装完是白屏」这一体验未在无运行时的机器上验证 |
| ARM64 | 目前只出 x64 包 |
| 非默认 `%LOCALAPPDATA%`（漫游/重定向） | 未专门构造 |
| 跨大版本升级（如 1.0.0 → 1.2.0） | 覆盖安装路径已覆盖，但跨版本迁移逻辑本身没有版本差异可测 |

## 八、版本号：Windows 要不要和 Android 同步

现状：Android 是 `v1.50.43`，Windows 是 `1.0.0-beta.4`，两套完全独立。

**建议：不要同步数字，但把「对应哪版前端」记进产物。**

理由：

1. 版本号应当表达「这个平台自己改了多少」。`1.50.43` 是长期累积的结果，
   Windows 才起步；对齐到 1.50.x 会让 Windows 首个正式版凭空跳过 1.0~1.49，
   用户会以为漏了几十个版本。
2. 两条发布线**本来就该能独立走**：改窗口行为不必为此发安卓包，改前端文案也不必强推 Windows 升级。
   绑死编号之后，「只修壳」也得升版本，「只改前端」也得升版本，发布记录会失去信息量。
3. 真正会混淆的不是编号不同，而是「同号不同物」——用户看到 Windows 1.50.43 会以为和安卓那一版内容一致，
   实际壳完全不一样。

落地方式（推荐）：

- Windows 走 `1.0.0` 起的独立线，Android 保持 `1.50.x`。
- 在 Windows 程序集里加一条 `AssemblyMetadata("FrontendVersion", "1.50.43")`，
  「设置 → 关于」显示成 `Windows 1.0.0 · 前端 1.50.43`。
  （`UpdateService` 已按 `+` 截断，往 `InformationalVersion` 里塞元数据也不会影响版本比较。）
- Release 标题写成 `Windows 1.0.0 (前端 1.50.43)`，两边一对就清楚。

如果坚持要「用户看到同一个号」，那就从现在起把 Windows 也并入 `1.50.x`，
从 `1.50.44` 开始，并且此后前端每次发版都必须跟着发 Windows —— 代价是 Windows 版本号不再表达自身变更。
